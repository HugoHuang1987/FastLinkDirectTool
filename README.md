# FastLink 直连助手

## 2.6.6 双网模式与托盘窗口（2026-11-25）

- 模式一保留原 FastLink 按规则直连。模式二为有线公司内网 + Wi-Fi 外网；模式三交换角色，为 Wi-Fi 公司内网 + 有线外网。两张物理接口必须明确选择，不根据网速或私有 IP 猜测。
- 双网模式不依赖 FastLink；不要与活动的 FastLink / aTrust 隧道同时启用。公司准入、双网许可和真实外网连通性分别核验，不绕过企业安全策略。
- 双网窗口点“－”收进托盘，分流继续；双击托盘图标或选择“打开网络模式”恢复。点“×”、“退出助手”或托盘“退出并清理”仍执行安全清理，不应当作最小化使用。
- 原规则仅在本机导入，内外网分类保存在本机 `dual-profile.json`。公开代码不预置任何公司的专属域名、内部地址或用户配置；首次迁移时公司/未知目标须自行分类，已保存的分类不受影响。
- 域名对应 IPv4 地址走指定接口；已核验的外网 IPv6 默认出口可保留。不是防火墙级防泄漏方案，应用自带代理、DoH、共享 IP、现有连接及其他 DNS 记录类型仍有边界。
- 现场验证范围：2.6.5 模式三的公司 OA 与研发系统已到达登录页，普通互联网访问正常，用户确认当前功能可用。该验证不代表登录成功、邮箱认证通过或所有网络环境都已验收。
- 2.6.6 托盘改动已通过离线 UI/网络模拟及回归测试；安装、实机托盘恢复和更新后的业务验证须另行记录。模式二实机完整验收、重启/重连恢复、偶发慢 DNS 和状态忙碌误报仍是待验证/改进项。
- 维护时禁止强制结束持有 DNS 规则的助手。先正常安全退出并核实清理，再替换程序；保留原程序、规则及恢复记录备份。不会因升级重新启用诊断任务或定时 AI 分析。

离线验证与候选编译：`tests/Run-RegressionTests.ps1`、`tests/Run-NetworkModePlanningTests.ps1`、`tests/Run-DualNetworkTests.ps1`、`Build-Candidate.ps1`。候选编译不启动或替换正在运行的助手。完整边界见 [网络模式设计](NETWORK-MODES-DESIGN.md)。

## 2.5.1 清理失败时的保护修复（2026-10-30）

- 安全清理开始时，先暂停并等待已开始的 DNS 路由写入结束；清理待完成期间，后台 DNS 请求不再添加路由或续写路由有效期，也不会在短暂熔断结束后自行恢复写入。
- 先核实移除自有 Windows DNS 规则，再移除自有系统代理例外；其中任何一步失败都保留 DNS 监听，不提前停止服务或清空依赖路由。显式安全清理仍可继续，成功清理并重新开启后恢复写入。
- 规则更新中的路由失败同样进入安全暂停，健康日志增加 `route_dns_writes_paused`。新增非侵入测试覆盖阶段顺序、失败门禁、在途 DNS 请求和并发排空。
- 这修复的是异常后的保护缺口，不宣称解决了 Windows 路由/PowerShell 命令变慢的根因。不改变用户规则、FastLink 节点、Wi-Fi、自动重启选项或定时诊断任务。

## 2.5.0 新版系统代理兼容（2026-10-26）

- 支持 Fastlink 极速版 7.2.3 的 `ApexCore` 系统代理模式，保留旧版 FastLink 虚拟网卡模式。只有同目录的 Fastlink 主程序、受支持核心以及回环代理端口的进程归属全部匹配，才自动启用；不把 aTrust 或其他本机代理当作 FastLink。
- 在 DNS/路由规则之外，将直连域名合并到 Windows 系统代理例外。保留用户和 FastLink 原有例外；关闭直连或安全退出时只移除本助手新增的部分，不改变代理地址、代理开关或 PAC。
- 精确域名、IP、`.example.com`（含主域和子域）与 `*.example.com` 可用于系统代理分流。该模式暂不支持 `?`，遇到此规则明确报错，不扩大成 `*`。旧版 TUN 的 `?` 支持不变。
- Wi-Fi/DNS/网关及代理身份变化沿用稳定 8 秒后刷新机制；新版无 TUN 时，未匹配 DNS 查询使用当前物理网络 DNS，不再使用不存在的 `198.18.0.2`。同一 FastLink 代理覆盖例外列表时，每 10 秒轻量检查，仅内容变化时补回。
- 所有权状态写前持久化、写后读回。外部并发变更无法安全判断时停止操作并保留清理状态，绝不覆盖整份用户设置。新版自动重启暂不启用，不因故障主动重启 FastLink 或切换 Wi-Fi。
- 系统代理例外只影响遵从 Windows 系统代理的应用；应用自身固定代理设置仍需另行配置。公司内网仍须公司 Wi-Fi 或获准的公司 VPN，切换 Wi-Fi 不保证已有连接不断线。
- 构建和回归测试需同时包含 `FastLinkConnectionCompatibility.cs`、`SystemProxyBypass.cs`。适配不重新启用已停用的详细诊断采集任务，也不增加定时 AI 分析。

## AnyDesk 轻量诊断采集（2026-10-09）

- 复用 `FastLinkDiagnosticMonitor` 的隐藏后台进程，不增加任务、常驻进程或定时 AI 分析，不重启 AnyDesk / FastLink / 直连助手，不修改路由。
- 无会话时约 30 秒检查进程及日志增量；AnyDesk 空闲时最多每分钟一条性能记录。识别到会话后每轮采集（最短 10 秒，实际间隔还包括原网络检查耗时）。单次连续 3 次超过 250 ms 或出错时退避到 60 秒。
- 仅保留白名单事件：会话起止、中继选择、点对点失败、画面调整超时、远端关闭原因。增量读取每次最多 256 KiB，启动或日志轮换最多回读 1 MiB；不改变 AnyDesk 自己的日志级别。
- 记录本机 CPU、可用内存、AnyDesk CPU/内存、Wi-Fi 信号和链路速率、现有网关探测的延迟、网卡吞吐、系统 TCP 重传增量和 AnyDesk IPv4/IPv6 TCP 端点。额外采集没有网络探测或测速下载。
- 不录屏、不抓包、不读取键盘/剪贴板/远程文件内容，也不保存 AnyDesk 账号、远端 ID、口令或令牌。IP/端口和本机进程号只保存在本地诊断目录。
- 文件位于 `%LOCALAPPDATA%\FastLinkDirectTool\diagnostics\anydesk`，最多 14 天、10 个各不超过 5 MiB 的日志文件（约 50 MiB），`status.json` 表示采集器当前状态。滚动日志只删除本模块专用命名文件。
- 按需运行 `diagnostics\Get-AnyDeskIncidentReport.ps1 -LookbackHours 24` 生成本地报告；报告不会被定时触发。专项测试入口：`tests\Run-AnyDeskObserverTests.ps1`。
- 边界：只能观察本机，不能替代连接端日志；网卡吞吐及 TCP 重传包含所有应用；FastLink 虚拟地址不证明绕海外代理；没有每会话 FPS、端到端 RTT 或视频负载数据，阈值只能提供排查线索。

## 2.4.5 连续编辑规则不漏刷新（2026-10-09）

- 修复上一批规则刷新期间继续添加、删除或切换内网直连选项时，修改只保存但未实际加载的问题。
- 修改按版本排队；当前操作结束后，自动合并应用最新完整列表，不并行刷新，也不逐条重放旧列表。开启直连和切换网络期间的修改同样保留。
- 明确区分“已保存等待刷新”和“最新完整列表已生效”；失败暂停自动重试，安全清理门禁保持不变。
- 记录排队版本、实际完成版本、规则数量和耗时，不记录账号凭据。包含连续添加 AnyDesk 两个域名、批量增删、忙碌门禁及失败暂停等 43 项非侵入回归测试。
- 本版不更改 FastLink 节点、Wi-Fi、自动重启开关或计划任务；域名直连不保证 AnyDesk 两端能够建立点对点连接。

## 2.4.4 网络切换失败保护（2026-09-28）

- 新 Wi-Fi / 网关 / DNS 连续稳定至少 8 秒后才自动刷新，避免切换抖动时反复处理规则。
- 网络刷新失败后暂停自动重试，只提示一次；清理未完成时保留 DNS 服务，但不再自动刷新、应用新规则或清理过期路由。点击主开关进行安全清理后再开启。
- 批量 DNS 清理上限调整为 120 秒，应用规则按数量给予 120–300 秒的有界时间；仍须验证退出码、未超时与实际规则回读，不能因延长时间而忽略失败。
- 日志增加规则处理阶段、完成数量、耗时和网络刷新结果，便于区分系统命令变慢与规则不完整；不启用定时 AI 分析。
- 新增网络抖动、失败暂停、手动恢复和 38 条混合规则等非侵入回归测试；不会自动重启 FastLink 或切换 Wi-Fi。

## 2.4.3 安全清理修复（2026-09-16）

- DNS 规则的应用与清理必须同时通过退出码、超时状态和实际回读检查；只处理本助手标记的规则。
- 清理未确认成功时保留 DNS 监听与所需路由，显示“清理未完成”，禁止自动重新开启；可点击“重试安全清理”。
- 托盘“退出并清理”在安全清理成功后才退出。不要通过任务管理器强制结束助手；系统强制结束、断电或强制关机无法由进程内保护保证清理。
- 开启过程中的失败（包括路由添加失败）进入受控回滚；初始化清理失败时停止自动启动流程。
- 构建脚本不再强杀正在运行的助手；须先通过托盘安全退出，再更新程序。
- DNS 服务器直连路由会回读验证；拒绝为 FastLink `198.18.0.0/15` 虚拟地址建立物理直连路由。
- 非侵入回归测试入口：`tests/Run-RegressionTests.ps1`。不会创建实际 DNS 规则或更改路由。
- 大规则集超出 Windows 命令行长度时使用临时脚本并自动清理；覆盖 100/200 条规则的回归测试。
- 开启失败后暂停自动重试，避免每几秒重复弹窗；可手动重试，或在 FastLink 下次重新接通时恢复。

- 自动检测 `FastLink Tunnel`。
- Fastlink 启用后自动打开直连模式，关闭后自动清理。
- 支持精确域名、域名后缀及 `*` / `?` 通配规则。
- 可选直连 RFC1918 私有网段，默认关闭；仅在域名/IP 精确规则仍不足时启用。
- 通过 Windows 登录计划任务自启动；平时驻留系统托盘。
- 域名规则使用热更新，不再清空全部动态路由；运行日志保存在程序目录的 `runtime.log`。
- 重复 DNS 查询会自动合并并短时缓存；动态路由维护每分钟最多运行一次，且不会并发堆积。
- 路由命令一旦超时会短暂熔断，避免 Windows 路由栈异常时产生大量排队任务和界面卡死。
- 检测到 Wi-Fi、DNS 或网关切换后，会自动刷新直连规则。
- 检测到物理网络丢失有效 IP 后会记录诊断信息；只有用户明确打开“网络异常时自动重启 FastLink”后，才会续租网络地址、重启 FastLink 并恢复直连规则。
- 自动恢复时会记住断线前的 Wi-Fi 并优先重连；手机热点等其他网络仅作为原 Wi-Fi 暂不可用时的临时兜底。
- Wi-Fi 切换期间会优先等待新网络稳定，避免把正常切换误判为断网。
- FastLink 显示已连接但代理连续约 50 秒检测失败时，默认只记录日志，不重启 FastLink；用户可在界面中主动开启自动恢复。
- 代理探测有严格 7 秒上限；自动恢复后会再次验证实际代理传输，而不只依赖 FastLink 界面的“已连接”状态。
- 自动重启开关默认关闭。主动开启后，必须连续两次代理探测成功才算恢复；恢复失败后退避 10 分钟，恢复期间暂停动态路由清理。
- 独立健康事件日志位于 `%LOCALAPPDATA%\FastLinkDirectTool\health-events.jsonl`，记录代理事件、恢复耗时、DNS 合并/缓存、路由超时及 FastLink 核心状态；可从托盘菜单直接打开。

规则示例：

- `portal.example.com`：只匹配这个域名。
- `.example.com`：匹配 `example.com` 及其所有子域名。
- `*.example.com`：匹配所有子域名。
- `api-?.example.com`：`?` 匹配一个字符。
- `http://10.0.0.25/app/`：自动提取 IPv4 地址并直连，路径会被忽略。

首次运行会申请管理员权限，因为添加直连路由和 DNS 规则需要管理员权限。

如确实需要自动断网恢复，请先在助手中主动打开“网络异常时自动重启 FastLink”，再在 FastLink 的“应用程序”设置中开启“自动运行（应用打开时自动运行）”。

如需排查偶发断网，可运行 `diagnostics/Monitor-FastLink.ps1` 留存物理网络、FastLink 节点（自动识别 `10131` / `10151`）、核心出口连接、系统 TCP 失败/重传计数及 ChatGPT 传输状态；Windows 计划任务通过 `Run-Monitor-FastLink-Hidden.vbs` 在后台启动采集器，避免被 Windows Terminal 接管并弹出窗口。`Get-FastLinkIncidentReport.ps1` 可按时间自动关联健康事件与采样证据。诊断日志默认写入 `%LOCALAPPDATA%\FastLinkDirectTool\diagnostics`，不会提交到仓库。
